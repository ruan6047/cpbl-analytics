# CPBL 季後賽專頁 PRD v2

# 產品定位與已定案範圍

版本：PRD v2。日期：2026-10-14（Asia/Taipei）。產品：公開、免費、單人維護的中華職棒 [CPBL] 數據站。新路由：`/playoffs`。受眾：一般球迷；手機優先 [Mobile-First]。交接對象：Claude Code。

本規格整合季後賽 PRD v1 與架構審查。目標是讓球迷在同一頁查看系列進度、兩隊背景、資格名單及下一場觀戰重點，並沿用既有計算與來源契約。需求優先序：資料正確、缺資料看得出來、手機易讀、降低維護與重複查詢成本。

## 已定案

| 決策 | 必須遵守的行為 |
| --- | --- |
| 32 人名單不可變 | 每隊每系列提交一份已核實官方名單；提交成功後不能新增、刪除或替換會員；同內容重送可冪等 [idempotent] 返回原結果 |
| 最有價值球員 [Most Valuable Player, MVP] 以官方為主 | 單場 MVP 讀官方紀錄；系列 MVP 讀官方系列獎項；未公布、未取得分開標示，不自行推選 |
| WAR 暫不實作 | 不新增勝場貢獻值 [Wins Above Replacement, WAR] 計算、資料管線、排行或季後賽估算；RE24/WPA 不轉換成 WAR |
| RE24/WPA 為補充 | 以得分期望貢獻、轉折事件補充官方 MVP；移除「本站數據 MVP」及以 RE24 第一名授予 MVP 的要求 |
| 三項門檻 | 第五節提出 v2 建議預設值；屬本站產品規則，尚未經 CPBL 回測；調整必須版本化，不准實作者私自改值 |
| 本次交付 | 只產出規格與交接，不授權程式實作、資料寫入或部署 |

## 範圍與退場

四區保留穩定識別：1 系列賽表現、2 隊伍表現、3 選手名單與表現、4 觀戰重點。手機排序按狀態調整；桌面維持清楚的閱讀層級。

`/standings?seg=3` 縮為系列比分與連往專頁的入口。`/games/{sno}/report`、`/preview` 的完整產品內容由專頁承接，舊網址保留對應轉址 [redirect]。不得把歷史網址全部轉往目前下一場。舊應用程式介面 [Application Programming Interface, API] 先保留，除非已查明所有呼叫端並另有移除範圍。

單場 `/games/{sno}`、球員 `/players/{id}`、球隊 `/teams/{code}`、`/matchups` 繼續提供深入內容。第 3 區以底部抽屜 [Bottom Sheet] 查看摘要，第 4 區以原地手風琴 [Accordion] 展開依據。

不在本次建立傷兵遞補名單、健康風險模型、即時訓練、自由調權重或可用性機率。官方缺資料時須顯示具體未知原因。

# 聯盟規則與資料契約

## 聯盟規則來源

權威為本地 `docs/reference/聯盟規章.txt` 第 12 章第 60–68 條（PDF 頁 55–58）及 `docs/reference/裁判執法手冊規則補述.txt` 1.01(C)。`RULES_REFERENCE.md` 是索引，不能用摘要取代條文。特定年度賽程及讓勝對象由當年度官方公告確認；不以本規格固定任何球隊。

| 規則 | 系統要求 |
| --- | --- |
| 第 60 條：E 五戰三勝、C 七戰四勝；依上下半季冠軍組合，E 或 C 可能先勝一場 | E/C 均支援每隊 initial_wins；年度公告指定讓勝隊，不從比分反推 |
| 第 63 條：任一隊取得所需勝場即結束 | series decided 後停止下一場生成，未需進行安排隱藏；原安排保留供追溯 |
| 第 65 條：系列名單 32 人，其中外籍球員限 3 人；每場最多登錄 28 人；公布後不得更改 | 系列資格、當場登錄、先發陣容與可用性是不同概念；匯入會員不得由成績推導 |
| 第 66 條：九局完成前不可抗力中止為保留；九局完成後平手且不可抗力中止可成和局 | 完賽不等於分出勝負；E/C 和局合法，不一律判資料異常 |
| 第 67–68 條：順延與加賽依聯盟安排 | 場次可超過 G7；只接受官方安排，不能自行發明日期、球場或場號 |

外籍身分與資格已有可靠證據時檢查規則；未知不能用姓名、國籍外觀或國際化名字猜測。匯入的是官方已核定公告；本站不宣稱另行完成聯盟全部資格審查。

## 身分與系列勝場

公共單場識別為 `(year, kind_code, game_sno)`，kind E＝挑戰賽、C＝台灣大賽。底層 games 仍保留含 game_season_code 的實際主鍵；Join 必須遵守既有契約，避免倍增列。

`series_id` 至少包含年度與賽別，另綁定正式參賽隊伍與規則版本。`official_game_sno`、`series_game_no`、`announced_slot_id` 分開；保留續賽不是新 G，和局加賽由官方場序表示。單場連結必帶 year 與 kind。

每隊 total_wins＝initial_wins＋正式完賽的實際勝場。和局不增加勝場。讓勝不產生假比賽、球員出賽、球數、PA 或 MVP。任一隊達 wins_needed 即 decided；雙方同時達標、隊伍不符或官方結果衝突時回 unknown/conflict，不能取排序較前者為勝隊。官方更正後可撤回原 decided 顯示，保留修正證據。

# 賽事狀態與頁面行為

## 正交狀態

T0–T5 是佈局預設，不是只能向前的業務流程。由伺服器／共用純函式 [pure function] 以同一份事實及注入時鐘推導，不在瀏覽器各區獨立猜測。

- series_status：pending、active、decided、unknown/conflict。
- roster_status：missing、draft、submitted；逐隊保存，完整臨戰名單需雙隊提交。
- target_status：scheduled、live、suspended、final、postponed、unknown。
- starter_status：missing、partial、announced、changed、unknown；兩隊分開記錄。
- analysis_status：pending、partial、ready、reconciling。
- freshness_status：covered、pending_update、unknown。
- registration_status：當場 28 人登錄 confirmed、partial、unknown；不是系列 32 人狀態。

## 佈局與預設展開

| 狀態 | 判定及四區順序 | 預設行為 |
| --- | --- | --- |
| T0 預熱 | 本系列未有正式完賽、首場未確認 live、未符合 T1；1→2→3→4 | 展開隊伍比較；沒有正式系列數據則隱藏累計榜；名單已提交就展示，不因先發未公布仍放佔位 |
| T1 首戰臨戰 | 首場尚未開打、雙隊名單已提交且雙方先發有有效公告；1→4→3→2 | 展開觀戰重點與名單，收合隊伍比較；部分先發資訊可先顯示但仍標 partial |
| T2 場間／移動日 | 至少一場正式完賽、系列未結束、沒有進行中的目標場、下一場未雙方鎖定；1→4→3→2 | 顯示階段 A；不存在正式目標場時只顯示安排待定，不生成綁錯場號的推測 |
| T3 賽前鎖定 | 目標場未開打、雙方先發有有效公告；1→4→3→2 | 階段 B 取代目前主體；名單缺失仍可進 T3，各區獨立降級 |
| T4 比賽／賽後回顧窗口 | 已觀測 live；或可信 final 觀測起 60 分鐘內、且系列尚未 decided；1→4→3→2 | 強化固定錨點列 [Sticky Sub-nav]；當前比賽資料與下一場看點以場號標示，不能混在同一份快照 |
| T5 系列結束 | 正式勝場證據確認 decided；1→3→4→2 | 官方結果總結；名單預設系列實戰；歷史觀戰報告收合；隊伍比較改系列對照 |

判定優先序：正式 decided → 已觀測 live → 有效賽後 60 分鐘窗口 → 雙方公告 → 正式場間 → 預熱。延賽、保留、資料未知以可見狀態提示覆蓋，不用時間硬切。若下一場已實際 live，優先於上一場回顧窗口。

60 分鐘從可信 ended_at 起算；若只存在 first_observed_final_at，須標為觀測基準，不能當官方終場時間。兩者皆未知則不啟動計時窗口。60 分鐘只控製版面，不控制寫入、驗證、完賽判定或封王顯示。

挑戰賽 T5 顯示「晉級總結」，台灣大賽 T5 顯示「封王總結」。跨系列導流橫幅保留明確系列名稱；不把 E 的名單／成績當 C 的資料。

## 選擇、深連結與動態更新

建議 URL：`/playoffs?year=2026&series=C&game=1`。game 使用官方 sno；該頁已有 series，因此與 E1 不混淆。預設年度取既有賽季設定；預設系列沿既有 postseason journey 決定，使用者明確選擇優先。

四區錨點固定為 `#series`、`#teams`、`#roster`、`#watch`，不因排序改名。game 可選歷史觀戰版本；歷史閱讀不影響系列當前狀態。

首次載入／切系列才套預設排序。使用者已捲動、選球員或手動收合後，輪詢不能突然重排或搶焦點；更新目前區內容，必要時提示「有新賽況」。切系列取消舊請求或以 request token 丟棄過期回應；context_version 不一致不得拼接。

## 例外行為

- 延賽：保留 target 身分、舊先發公告及快照；改期後重新建立賽程上下文。原 A 失效，不移轉成新場次命中。
- 保留續賽：同 game key；不重算兩次出賽。原始比賽與續賽的實際投球日期分開用於負荷。
- 和局：已出賽與個人成績可累計，不計任何隊勝場；等待聯盟加賽安排。
- 雙重賽：同日兩場分別累計球數；連續日登板只算一個日期。
- 官方更正：更新目前統計版本，原發布與檢核紀錄保留。
- 完賽但 PA 未齊：更新官方比分/MVP，進階榜與名場面標待更新；T5 可先顯示正式冠軍，不等待分析。
- 當場登錄未知：32 人區完整保留；不得把名單內球員標成已確認當場可用。

# 四大區塊產品規格

## 第 1 區 系列賽表現

橫向場次卡採動態清單，支援加賽；區內可橫向捲動，頁面本身不水平溢出。只有真實正式場次能組單場連結；公告安排可展示，但不能據序號發明資料庫 [database] sno。

每張完賽卡顯示比分、官方 MVP、既有本場焦點、全場影響最大打席一句話摘要，連到單場賽況。暫定分析附狀態；保留、延賽、待更新分開。沒有焦點或摘要時省略該欄，不能套模板猜測。

累計榜：打者前 3、投手前 2，以本系列正式完賽集合計算，附 PA/BF、傳統成績與官方「單場 MVP ×N」。只屬該系列，不混 E/C；部分缺資料時顯示已涵蓋場次，不授予完整系列第一名。

打者 ΔRE24 文案：「相對局面得分期望，累計 +X.X 分」。投手原始 RE24 是打者視角，負值越好；展示正向壓制貢獻須轉號並標方法。沿既有分桶與記錄歸屬處理跑壘、打席中換人／換投，不能將整個 PA 一律歸最後投手。以未四捨五入的值排序，ID 決定顯示平手順序；相同展示值不聲稱有統計差距。

T5 主體：官方系列結果、官方系列 MVP、其他官方獎項（有來源才展示）、本系列得分貢獻與三大轉折。沒有官方系列 MVP 時不自選替代獎項。若獎項含共同得主或不同類型，按官方完整名稱與得主清單呈現，不壓成單一 ID。

三大轉折採同一指標：全系列候選 PA 的 abs(ΔWPA) 前 3，保留既有 WPA 可用性、參考資訊及事件門檻。若任一場的必要 WPA 來源不完整，整組降級成 abs(ΔRE24) 並註明；RE24 也未齊則顯示「已涵蓋場次轉折」，不能宣稱全系列前三。平手依官方場序、pa_index、穩定 pa_id 排序。可少於 3 筆，不硬湊；取定名單後依時間呈現，不將單場先截取的小集合再當全系列候選母體。

## 第 4 區 觀戰重點

### 4A 牛棚近期使用負荷

名稱使用「近期使用負荷」，綠／橘／紅旁有低／中／高文字；灰色是未知。這是球數與出賽日的描述，不是健康判斷、可用性機率或教練調度。

預設顯示名單中 #終結、#勝利組、#長中繼 投手；其他投手可展開，不因角色未標記被刪除。並列最近 3 次登板、最近 3 個日曆日球數、完整休息日、連續日登板、當日登板次數、當場登錄是否確認。角色是本站註記，官方數據與角色不混淆。

近三日跨 A/E/C；可靠觀測的其他正式登板也納入，無法涵蓋的活動在 scope 中揭露。目標場進行中時計入該場「目前已投」但標即時；歷史賽前報告保持凍結值。保留賽無法拆分實際投球日期時球數仍可展示，日期負荷標未知。

連續兩日登板時附本季「距前次登板一天的當次出賽 ERA」，從 A 分項／可對帳逐場數據取得，附出賽數、IP、ER 及口徑。ERA＝27×ER/outs，outs=0 為不可定義；不平均單場 ERA，不暗示連投導致該 ERA。

每隊聽牌＝自己的 total_wins 等於 wins_needed−1；面臨淘汰＝對手達此條件。可同時成立。任一隊符合則展開「殊死戰可能調度的先發候選」，列該隊休滿至少 2 個完整日曆日的輪值先發；這只是候選，須附當場登錄／官方待命證據。不得寫「全員確認待命」。

### 4B 先發對決與看點卡

階段 A：顯示推測候選、排名依據、截止時間、尚未公告；不使用官方先發樣式。階段 B：顯示目前有效官方公告、來源及觀測時間，另保留 A 的命中檢核入口。雙方部分公告時各隊獨立顯示，不等另一隊才展示。

| 卡片 | 必須包含 |
| --- | --- |
| 先發壓制力與特性 | A 例行賽 ERA、先發平均 IP、對指定球隊 ERA 與 IP、P/PA、GO/FO、兩好球解決率；先發平均 IP 只計官方先發，不混後援 |
| 天敵候選／優勢對位 | 沿既有 /matchups 統計核心；A 的已核資料 scope、PA、洞察依據；本季 OPS+、對戰 AVG、本系列近況各標 scope |
| 球風矛盾 | 固定 team_tag × player_trait 規則表；每項帶 rule_id、門檻、樣本閘門、依據及固定文字模板 |

現有洞察 API 對 E/C 回空；本頁以 A 例行賽背景沿既有閘門建立洞察，系列近況另列。保留覆蓋率、先驗可靠性、後驗可信度與敏感度檢查，不改成「PA≥某值即可」。單季先驗不足可用明確標示的既有生涯 A scope，不能無聲回退。洞察候選應在完整對手母體完成評估後，才與對方系列名單／目前先發匹配；不以縮小母體降低覆蓋門檻。

展開卡片顯示樣本、基準與配對，連往帶該球員／對手 scope 的 /matchups。沒有通過閘門的候選，顯示「目前沒有符合條件的對位」，不補排行湊卡。

賽後依第七節檢核，每一項顯示精確結果，如「投滿五局」「本場敲安」「公告命中」；保留未達標、不適用與未知結果，不只展示成功印章。

## 第 3 區 32 人名單與選手錶現

標題「系列賽 32 人資格名單」。切換「例行賽與對戰背景」／「本系列實戰數據」；T1–T4 預設背景，T5 預設系列。切換保留球隊篩選、排序與抽屜選擇。

小卡：姓名／官方守位、本站角色、已出賽 XG、官方 PR≥90 石油藍標籤、近 15 場背景與冷熱箭頭。PR 方向沿官方資料；無官方 PR 不補排名。只展示有可靠資料的標籤，完整能力圖與走勢在抽屜按需載入。

本季一軍沒有成績的名單球員仍顯示；可展示另標「二軍背景」的 D 成績，但不能補成 A 的 PR/OPS+。純代跑或守備出場亦可計 G；以完整官方出場證據判定，沒有 PA 不等於未出賽。

## 第 2 區 隊伍表現

# 三項門檻建議與依據

本節數值是 v2 建議預設，使用設定版本 `playoffs-policy/v2.0-proposed`。它們提供可重現的候選與顯示行為，尚未經 CPBL 歷史資料校準。不得宣稱聯盟強制休息規則、醫療安全界線、預測命中率或統計顯著性。

## 先發推測最低休息門檻

| 場景 | 建議預設 | 行為 |
| --- | --- | --- |
| 一般階段 A 候選 | 最後一次實際投球後，完整休息至少 4 天 | 可進主候選列表 |
| 短休候選 | 恰好完整休息 3 天 | 只在聽牌／淘汰戰展開「短休候選」，不自動升為主要推測 |
| 殊死戰後援候選 | 完整休息至少 2 天 | 僅出現在 4A 調度候選，不表示可先發或已待命 |

完整休息日＝max(0, 目標場台北日期−最後實際投球台北日期−1)。10/9 登板、10/14 比賽＝完整休 4 天。休息從「最後一次投球」起算，不能忽略中間後援登板；日後改期必須重算，但舊快照不覆蓋。

候選需：已提交名單、角色為輪值、最近 30 日內至少一次可靠正式先發證據、登板日期可核實、沒有官方不適用證據。沒有近期先發證據者可保留名單與說明，不自動推為主候選。

排序依序：完整休息日降序 → 最近 3 次正式先發的出局數中位數降序 → player_id 升序。前兩項均相同則展示並列候選，不以 ID 勝出宣稱單一推測。ID 只提供穩定顯示順序。兩隊各至多 3 位；只有唯一首位且證據齊備才發布單一推測，否則主體寫「候選未定」，候選集合不計命中率。支持分辨 opener：輪值註記與先發證據均須具備，不能把每個 GS 當傳統先發。

依據：4 日完整休息對齊一般職業先發輪值的保守展示基準；[MLB 官方詞彙頁](https://www.mlb.com/glossary/positions/starting-pitcher)描述常態為 4–5 日。這不是 CPBL 法定門檻。3 日短休與 2 日後援列出是本站情境設計，沒有健康或成功率含義；30 日近期證據窗口防止僅憑久遠先發紀錄推測，亦為產品預設。

## 牛棚近期使用負荷門檻

D 為目標場台北日期；P1/P2/P3 分別為 D−1、D−2、D−3 的正式比賽球數總和。S2=P1+P2，S3=P1+P2+P3。C 為截至 D−1 連續日曆日登板數；Q 為 D 當天、截至觀測時間的登板次數；P0 為 D 當天截至觀測的總球數。同日不同場分別計球數，日期只算一天。

| 等級 | 命中任一條件 |
| --- | --- |
| 高負荷 紅 | P0≥30，或 P1≥30，或 S2≥45，或 S3≥60，或 C≥3，或 Q≥2 |
| 中負荷 橘 | 尚未達紅色，且以下任一成立：P0≥15、P1≥15、S2≥25、S3≥40、C≥2、Q≥1 |
| 低負荷 綠 | 來源完整且以上都未成立 |
| 未知 灰 | 所需登板覆蓋／球數／實際日期未核完整；不能把缺列當零 |

判定優先序：資料是否完整 → 紅 → 橘 → 綠。灰色仍可列已知球數與「資料不完整」，不輸出可用性。T4 的 Q／當前球數來自即時觀測則標即時；賽前版本固定截止值。一般先發不套牛棚綠燈；列入殊死戰候選時展示最近球數與休息日，不直接宣稱低疲勞。

依據：15/30 是單日較短／較長後援工作量的產品分段，25/45 與40/60 累計門檻讓連續多日中等球數也能被看見，C/Q 補捉球數單看會漏掉的頻繁登板。這些數字不是研究已證實的臨界值。既有出賽紀錄可直接解釋每個觸發原因，維護成本低。[後援工作量研究](https://tht.fangraphs.com/how-an-ace-performance-impacts-reliever-workloads/)同時考量球數、登板及休息；只能支持多維描述，不能替本頁具體門檻背書。未觀測熱身球與牛棚練投，不納入球數。

## 冷熱箭頭窗口與變動門檻

scope 固定本季一軍例行賽 A，截至當前背景截止點；季後期間標題「例行賽末段走勢」。不因 E/C 切換就混入其 PA 或改聯盟基準。

比較兩段不重疊窗口：W1＝最近 15 次個人出賽；W0＝緊接在前的 15 次個人出賽。每窗必須有 15 次，並沿既有出賽定義。兩個窗口使用同一年度、同一份聯盟基準與未四捨五入率；先加總原始計數再計算。

| 角色 | 每窗樣本底線 | ↑ 較前段上升 | ↓ 較前段下降 | 平穩／資料不足 |
| --- | --- | --- | --- | --- |
| 打者 OPS+ | AB≥30，率分母有效 | W1−W0≥15 點 | W1−W0≤−15 點 | 差在 (−15,15) 顯示平穩；不足標樣本不足 |
| 投手 ERA+ | outs≥30（10 IP），率分母有效 | W1−W0≥20 點 | W1−W0≤−20 點 | 差在 (−20,20) 顯示平穩；不足標樣本不足 |

ERA+ 高代表較好；不能反向畫箭頭。任一窗 ERA=0 導致現有 ERA+ 不可定義時，保留 ERA=0.00 和樣本，但不造 infinity/999 或熱箭頭。未滿 30 次個人出賽仍可畫既有滾動圖，只有比較箭頭缺席。

依據：15 場、打者 AB≥30、投手 10 IP 沿現有 trend.py 視窗與小樣本閘門；兩段不重疊防止以高度共享資料的相鄰滾動點放大單場變動。OPS+ 15／ERA+ 20 是讀者可理解的最小顯示變化量；ERA+ 對低 ERA 的倒數變化較敏感，故採較寬門檻。這不是顯著性檢驗，文案用「較前 15 次出賽上升／下降」，不宣稱預測未來。

## 身分解析與缺資料

1. 明確 ID 先查主檔及同隊年度身份證據；ID/name 不符回衝突。
2. 無 ID 時，指定年度／球隊範圍內的精確姓名只有唯一候選才能自動解析。
3. 別名只走已核實映射；不做猜測式模糊配對。
4. 多重命中或未命中停在草稿，列候選 ID、官方姓名、年度／隊伍證據供消歧。
5. 無本季 A 成績不影響身分與提交；沒有正式主檔身份則先補身份，不創建假 ID。

official_population 的現有固定 E 名單與其來源 metadata 可作為已核資料遷入來源；不可把年度 team_roster 全部當季後名單，也不從有成績的人自動湊 32 人。

## 提交流程

貼文字 → 解析預覽 → 32 個唯一身份及來源校驗 → 單次原子提交。原始文字留存；canonical membership 依 ID 與官方守位排序計算 membership_hash，忽略空白、列序與戰術角色，另留 source metadata。來源網址／公告日期不同須作為來源差異明示，不暗中改變已提交資料。

提交約束：

- 每 team、series 只能一份 submitted membership；恰好 32 個唯一 ID、非空官方來源與對應系列。
- 不足、超過、重複、身份未解決或官方守位衝突一律不能提交。
- 同 membership／來源內容重送回原 roster_id；不重建、不重新計算提交時間。
- 不同會員、守位或來源的重送拒絕，回清楚差異；無一般修改／覆蓋端點。
- 兩個競爭提交由數據庫唯一約束保證至多一個成功。
- 名單發生傷勢／禁賽不變會員；可另附官方可用性觀測，未知保持未知。
- 本次不建立中途遞補功能。本站匯入錯誤若需修正，停止該名單對外聲稱已核並提出例外處理，不以 routine 更新繞過不可變約束。

戰術角色是本站註記，可保存獨立版本；變更不改變32 人會員。歷史快照固定當時 annotation_version，不能回改原推測依據。

# 賽前快照與賽後檢核

## 發布與凍結

每個正式目標場分隊生成 A 候選／單一推測，B 公告與固定看點。A、B 是附加版本，不覆蓋；目前展示指向最新有效版本，歷史閱讀綁定指定版本。

A 在發布時保存 target_game_key、published_at、cutoff_at、來源版本清單、algorithm_version、policy_version、membership_hash、annotation_version、推測 ID/候選列表、排序依據與所有可檢核條件。不由頁面開啟才生成，以免沒有訪客即沒有預測紀錄。

以公告證據判斷時序：每隊評分 A 必須早於該隊「首次已觀測有效官方先發公告」。首次開賽觀測亦作上限。若官方公告時間只有日期或來源早已公布但精確時間不可覈實，標「公告時序未核實」，不算嚴謹的賽前命中。不以 fetched_at 冒充 announced_at；晚到系統的官方資料不能證明 A 是公告前預測。

評分基準 A＝當前賽程上下文內、首次公告界線前最後一份合法已發布 A。同內容重跑不新建；實質來源／推測改變新增版本，舊版本保留。只許最終基準 A 進入單一命中統計，不能事後挑最有利版本。

B 保存選中的公告 revision 與來源，引用被比較 A。兩隊分別可從 A 進入 B；整體鎖定需要雙方確認。B 的「公告命中」綁定當時公告；之後臨時換投不改歷史 B，另發 B revision，當前蓋章指新有效 B。實際先發命中另依據官方 box。

改期使原 A 的時距與負荷上下文失效：保留但 invalidated，若尚未正式公告可發新上下文 A。已有先發公告時不能重新發 A 並算「公告前命中」。保留續賽不發新的首場先發預測；恢復投手另作為觀測。

系列結束停止下一場發布。沒有真實 target 身分不建立可評分報告。T5 紀念冊保留全部有效、未命中、未知與失效版本及出處。

## 檢核資料模型

| 實體 | 保存內容 |
| --- | --- |
| watch_revision | series_id、target_game_key、phase、revision_no、來源 manifest、各時間及精度、各算法版本、固定 payload、supersedes_id／比較 A 引用 |
| watch_check | revision_id、check_id、rule_version、subject_id、opponent_id、條件、threshold、scope、適用條件 |

語意內容不可回寫；生命週期 current／superseded／invalidated 可另表保存。相同來源與 evaluator 重跑返回同結果；結果來源改變新增 evaluation。完整歷史 A→B→A 來源回改必須保留，不能用全域 payload_hash 去重丟掉第三次觀測。發布 transaction 與系列/場次鎖粒度固定，避免併發生成重複版本。

API 只讀；發布與檢核由有寫入權限的離線命令／既有每日鏈事件執行。單次發布在同交易 [transaction] 完成，成功後原子切換 current 指標；失敗時繼續展示上一個已發布版本並標待更新。

## 結果狀態與布林規則

結果為 pending、met、not_met、not_applicable、unknown、invalidated。pending＝尚未終場／所需同步尚未完成；unknown＝應有證據但缺失、衝突或無法覈實；not_applicable＝必要對戰/出場條件沒有發生；invalidated＝目標／前置上下文失效。missing 不得轉換為 False。

| check_id | 適用與必要證據 | met 的精確條件 |
| --- | --- | --- |
| starter_announcement_match | 合格單一 A、指定隊有效 B、公告前時序可核實 | A.player_id＝B.announced_starter_id |
| starter_actual_match | 合格單一 A、正式 final、box 確認實際先發 | A.player_id＝actual_starter_id |
| starter_five_innings | 被點名者是實際先發、正式 final 且 box 完整 | recorded_outs≥15 |
| batter_hit_any | 被點名打者有≥1 正式 PA，正式 final 且打擊 box 完整 | official_hits≥1 |
| batter_hit_vs_pitcher | 指定打投配對有≥1 正式記錄歸屬 PA，完整配對事實 | pair_official_hits≥1 |

兩隊先發各自檢核；沒有單一 A 則 prediction check 不適用。投手換人時舊五局看點不適用，不能判未達標。純代跑／守備沒有 PA 則安打檢查不適用；有 PA 但0H 才 not_met。配對按官方記錄歸屬判定，換投／代打規則沿 canonical 核心，不僅比對結束時名字。

布林 [Boolean] 只在適用與證據齊備後計算。局數存整數 outs，5.1 不是十進制5.1。官方修正後重新評估新版本；舊結果可稽核。

「敲安」印章只驗本場事件，不代表天敵洞察或預測能力被驗證。主文使用具體印章，不用單一「命中／達標」遮蓋適用條件。歷史冊的成功率若展示：分 check 計算 met/(met+not_met)，同屏顯示可評估數與所有不適用/未知數；不把不同 check 混成總命中率，未有充足發布歷史不展示百分比。

## 分區讀取面

| 讀取面 | Payload | 載入 |
| --- | --- | --- |
| overview | 系列進度、真實場次、比分、官方 MVP、輕摘要、佈局狀態、version/coverage | 首屏伺服器渲染 [Server-Side Rendering, SSR] |
| watch | 指定場 A/B、公告、負荷矩陣、少量已過閘門卡與檢核 | 第4 區接近 viewport/展開；T1/T3 優先 |
| roster | 兩隊32 人輕摘要、PR 標籤、近況箭頭、系列傳統計數 | 第3 區接近 viewport |
| comparison | 兩隊 A／對戰／系列比較 | 第2 區展開／接近 viewport |

API 具體路徑在規劃階段固定，可擴現有契約；不要求為了四區機械建立四支重複數據端點。讀取面各自有 status，不以空數組掩蓋異常。

避免 N+1 查詢：ANY 參數批次讀64 人；PARTITION BY player_id 批次取滾動窗；聯賽基準／對位先驗每 source version 一次；PA 事實批次加載 published builds 與 RE 矩陣。不能64 次調用球員完整端點，也不能每場通過 HTTP 完整 games 頁再拆數據。series summary 不要每請求重掃全 A box；背景預聚合，數據修正後重建。

首屏不包含64 人完整走勢、雷達圖、逐球及逐打席詳情。圖表按需加載 [lazy load]、保留等高佔位與文字摘要，避免首次渲染 [hydration] 負擔及版面位移。

## 一致性與快取

每份 response 帶 series_id、target_game_key、context_version、source_manifest、as_of、coverage 及算法版本。區間版本不一致時重取 overview 後只重取受影響區，不能顯示 C1 先發配 C2 牛棚。只讀聚合沿現有 REPEATABLE READ READ ONLY；跨 HTTP 請求靠 version pin，事務隔離本身不足以保障跨請求一致。

快取 [cache] 鍵包含 series、section、source manifest hash、metric/policy version、roster hash 及 target key；不能只用 year 或最後 refresh 時間。不是新建通用緩存平台的要求，優先復用現有基礎設施。

- 32 人提交內容不可變，長期緩存；角色注記另帶版本。
- A 背景在 source 更正時失效；不用對64 人每次重算。
- final／PA 建置發布後更新系列聚合；缺新來源時保留舊快照並明確待更新。
- 官方先發、延賽與當日登記變化觸發 watch 版本；不依客戶端重寫。
- 頁面可見時輕量 overview 默認30 秒輪詢，T4 活躍狀態10 秒；暫停隱藏頁面，網絡失敗退避，避免每次輪詢重跑重查詢。
- 控制狀態應用緩存不超過輪詢間隔；舊 client 默認600 秒不能用於臨戰狀態。持久數據讀緩存按 source version 管理。
- 若既有同晚事件鏈不能覆蓋新發布／快照流程，規劃必須顯式列出寫入者、觸發、失敗重跑與待更新呈現，不以「等每日排程」替代同日晚間要求。

## 前後端責任與格式

FastAPI 只讀、Python 計算；Next.js 渲染、選擇與互動；前端不重做統計門檻、完賽或系列勝場。原公共頁面與 playoffs 吃同源結果。SQL 參數化，conn()管理連接；新增遷移接續當時最大編號、冪等，不修改舊遷移。

為官方系列獎項和不可變名單定義有限來源介面；官方獎項若既有表不能表達 scope／多得主，可新增窄範圍離線匯入，不擴成通用 CMS，也不在公開 API 建立無授權管理寫入。

手機驗收至少375px 與390px；固定錨點不遮標題、單頁無水平溢出、觸控目標44px、狀態不只靠顏色、抽屜與 accordion 鍵盤與焦點正確。

## 防呆守則

- game_sno 不是全站唯一 ID；所有單場連結帶 year/kind。
- 不從公告 G 號發明正式 sno，不由 E 推 C 的資料庫場號。
- 不從非零比分、過去時間或 refresh 成功判斷完賽。
- 不讓獲勝門檻、官方 MVP 與分析齊備綁成同一個 ready。
- 不把名單資格或角色當實際先發／當場可用證據。
- 不把 NULL、缺行或沒有一軍數據當0；未滿32 的名單不能提交。
- 不以 RE24 或 MVP 次數取代官方系列獎項；不實現 WAR。
- 投手 RE24 正負、打席歸屬、outs 及比率統一按共享核心。
- 同 series 聚合不混 E/C；近期投球負荷才跨系列。
- 不用 team_current 默認半季值代表全年。
- 不平均球員率、單場 ERA 或已四捨五入 OPS；先聚合原始計數。
- 不因單系列結果好壞自動調疲勞／休息／箭頭門檻。
- 不在 GET 寫入、發布、爬取、訓練；不用訪客請求觸發快照。
- 不為滿足“前三名／三大事件／三張卡”製造候選。
- 不將 WPA 統計描述稱為預測準確率；不從卡片印章驗證統計洞察有效性。
