## 問題陳述

查核者的獨立性要求（新 context／跨家族／人工／兩者皆須）目前**只存在於卡面〈查核〉欄的自由文字**裡。`review_prompt.py` 為了把它帶進查核提示詞，必須從中文自由文字反推流程門檻——**這條路線已被證實失敗**。

`DEV-REVIEW-PROMPT-GUARD1` 連續三輪被同一位跨家族查核者以更根本的反例打穿，三次是同一個錯的三種變形：

- iteration 0（`REVIEW-005`）：first-match scalar，「先跨家族查核，並由需求方人工核可」的 AND 被讀成 OR。
- iteration 1（`REVIEW-007`）：距離式正則，條件句「跨家族查核，**若失敗**或有疑問再人工核可」被讀成二擇一；同時別名寫死導致「跨模型或人工」被誤升為 AND。
- iteration 2（`REVIEW-009`）：格式字元直連 ＋ 全文 `search()`，否定句與引文中的字樣覆蓋真正要求——「不可由**跨家族或人工**智慧代理取代」的命中甚至是**把「人工智慧」從中切斷**。

中文沒有空白分詞，否定、引文、條件句可任意嵌套。**每一輪修法都更嚴謹，每一輪都被更根本的反例打穿，這不是實作品質問題，是路線問題。**

需求方於 2026-07-29 裁定拆卡：`GUARD1` 改為**停止推斷**（工具只保證 tier 下限、卡面原文照登、不宣稱上限），結構化欄位由本卡承接。

## 目標

讓「這張卡需要哪一種查核獨立性」成為**機器可讀的欄位**，自由文字只供展示與補充，不再決定流程門檻。

查核者建議的形態（**值域與欄名由本卡 Discovery 定案，不得照抄視為已定**）：

```

```

## 紅線

1. **不得再引入任何從自由文字推斷流程門檻的邏輯**——這是本卡存在的理由。
2. **缺欄位不得靜默放寬**：沒有欄位的卡，工具行為必須是「明示缺欄 ＋ 以卡面原文為準」，不得回退成「所以只要新 context 就好」。
