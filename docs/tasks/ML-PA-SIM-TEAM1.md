## 問題

`/matchups` 的**歷史實績**已可查「對某一隊」，但**打席模擬**只接受單一投手。使用者
希望模擬也能對一支球隊。

## 為什麼不能只在前端／API 平均

`pa_sim` 是「打者×投手」的經驗貝氏估計。要對一支球隊，就得把該隊投手群聚合成一個
虛擬對手，而正確的權重是**該打者未來實際面對每位投手的機率**，不是隊內投手的算術
平均：先發吃掉多數打席但一場只對上一位、中繼與後援的出場條件依局數與比分而異。
直接平均會產出「該隊的平均投手」——一個不存在的對手，且會系統性低估先發、高估
少出場的投手。

## 目標與驗收

- [ ] 明確定義聚合語意並寫進 API 契約：是「下一場預期先發」、「該隊本季實際面對
      分布」還是「全隊打席加權」；三者結論不同，不可混用同一個數字。
- [ ] 權重必須可追溯到官方出場資料（先發／中繼／後援場次與打席），不得用手調係數。
- [ ] **驗收基準**：聚合估計必須勝過「該打者對該隊實際打席的經驗分布」這個 baseline，
      否則直接用經驗分布（歷史實績已提供），不需模型。
- [ ] 樣本與不確定性揭露：聚合會放大不確定性，區間處理須明說方法，且沿用
      「非統計信賴區間」的文案紅線。
- [ ] fail-closed：投手群出場資料不足、或該隊當季名單變動過大時不輸出，不以聯盟平均補。

## 驗證與依賴

- 驗證：與經驗分布 baseline 的走查對照、權重來源對帳、fail-closed 契約測試。
- 依賴：ML-SIM1 已結案。與 `ML-PA-SIM-CONTEXT1` 無強順序，但若情境條件化通過，
      聚合需一併考慮情境維度（樣本壓力更大）。
