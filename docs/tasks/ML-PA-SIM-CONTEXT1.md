## 問題

現行 `pa_sim` 的七類結果機率是 **context-neutral**：只由打者、投手（與兩人直接對戰）的
經驗貝氏收縮估計決定，壘況、出局數、局數、比分完全不進入估計。使用者實際操作
`/matchups` 第二 tab 時，改變假設情境只會看到勝率影響變化，機率列一動不動，直觀上
不合預期。

棒球上情境**確實**會改變打席結果分布（滿壘時投手不敢投壞球 → BB 下降、K 型態改變；
兩出局得點圈打者更積極 → 揮空與長打同時上升）。這張卡要回答：**在本專案的資料量下，
把情境放進估計能不能贏過現行 context-neutral 版本。**

## 統計前提（先讀，避免走錯方向）

- **不得用「分格計數」實作**：全母體約 18 萬打席，按 8 壘況 × 3 出局切格後再乘打者×
  投手，每格樣本會碎到收縮後幾乎回到邊際估計——數字看起來變了，變的是雜訊。
- 正解方向是**把情境當特徵的模型**（如多項邏輯回歸／GBM，情境以 dummy 或分組
  進入），讓情境效應由全母體共同估計、再與打者×投手效應相加，而非各自分格。
- `ml-sim1-review` 的 leakage 紅線全部沿用：特徵只能用該 fold 訓練期資料，
  換人列（`is_change_player`）與 control event 過濾不得放寬。

## 目標與驗收

- [ ] 在與現行相同的走查回測切分（test 2021–2025）上，**條件化版本必須勝過現行
      context-neutral 版本**：combined LogLoss／Brier 皆改善，且 paired bootstrap
      CI95 上界 ≤ 0。打不贏就是 NO-GO，不得因為「情境理論上有影響」而採用。
- [ ] 校準不得退化：ECE 不高於現行值；分情境（至少壘況×出局）各自檢查校準，
      避免整體 ECE 掩蓋特定情境的偏誤。
- [ ] 效應量誠實揭露：若改善量落在雜訊水準（比照 weighted-WP 的 0.000092 前例），
      結論寫成 NO-GO 並封存，不上 UI。
- [ ] 通過時才開後續 UI 卡調整面板文案（現行文案明說「情境不改變結果機率」，
      模型改變後那句話必須同步改；未通過則現行文案維持正確）。
