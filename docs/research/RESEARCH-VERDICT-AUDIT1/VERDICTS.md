## §1 母體：指令窮舉，不是人工挑選

```bash
uv run python docs/research/RESEARCH-VERDICT-AUDIT1/scan_verdicts.py       # → verdict_scan.json
uv run python docs/research/RESEARCH-VERDICT-AUDIT1/build_verdict_list.py  # → verdict_list.{json,md}
```

`scan_verdicts.py` 以 `git ls-files docs/research` 列出**全部 122 個版控內 md／json**，
用兩層詞彙表逐行掃描：tier1 是判定語彙本身（`No-Go`／`unsupported`／`不採用`／`未通過`／
`不可行`／`❌`／`不成立`／`放棄`／`FAIL`…），tier2 是三準則的病灶語彙（漂移／覆蓋缺口／
小樣本／管線落後…）。json 另做遞迴結構化擷取，抓 `verdict`／`status` 類鍵的否定值。

詞彙表**刻意過度命中**（`失敗` 這種詞會大量誤中）：漏掉一份帶否定判定的報告，比多列十份
無關檔案嚴重得多。收斂交給第二階段人工三問，而**每一次排除都必須在 `dispositions.json`
留下理由**。

命中 638 筆（tier1 430），**重審母體 64 份**。派工包指定必涵蓋的 8 份全部在母體內，
另外窮舉出 `ML-OUTCOME-SIMPLE-LEAK2`、`ML-PITCHER-SCORELESS1/2`、`TEAM-STYLE1`、
`UX-PLAYER-FIELDVIZ1` 等 PM 分診未列的份數。

**覆蓋是機器保證的**：`build_verdict_list.py` 對母體與處置表做**雙向**比對，
missing 或 ghost 任一非空即 `exit 1`。首次執行就抓到一筆 ghost（`container-probe.md`
不在母體卻被我列了處置），修正後才通過——這條檢查不是裝飾。

逐檔處置表（class／裁決／理由，64 份全列）：[`verdict_list.md`](verdict_list.md)。分類法：

- **S 統計判定**（12 份）：否定判定由統計量／門檻／檢定產生 → 逐份回答三問。
- **S\* 機器 artifact**（5 份）：裁決繼承 parent 報告。
- **F 可行性／規則判定**（20 份）：由「資料是否存在、是否重複、規則是否蘊含」決定，
  不涉抽樣推論 → 只檢準則 1（母體或管線變動會不會使判定翻面），不套準則 2／3。
- **N 非否定判定**（27 份）：命中來自欄位值（`三振/第三好球觸擊失敗`）、爬蟲錯誤訊息、
  引用他卡結論、查核 PASS 敘述、流程卡封存 → 排除，逐項記錄理由。

## §2 方法：把準則 3 量化

準則 1 與 2 可以靠讀報告判斷（判定有沒有掛在會漂移的母體上？是不是幾筆個案撐起來的？）。
準則 3 難在「樣本不足以判定」與「測了，不準」的界線需要數字。本卡的判準是：

> **在「模型完全校準」的零假設下，該閘門的統計量會落在哪裡？
> 若零假設下的期望值已經超過門檻，那個門檻不是判準，是雜訊產生器。**

這招不是本卡發明的。`ML-OUTCOME-SIMPLE-LEAK2_RESULTS.md` §3.2 已經在本專案內用同一招
打掉固定校準斜率區間 `[0.8, 1.2]`（實測對誠實模型的偽失敗率 41.8%）；`GAME-RECAP-WP-VAL1`
自己也在 §5 用同一個道理否決了 v1 的逐季 ECE 0.025 門檻（「ECE 0.025 門檻低於單季雜訊底線，
**校準完美的模型也會經常超標**」）。**本卡只是把同一把尺套到 VAL1／CAL1 尚未受檢的那幾道閘門上。**

實作見 [`analyze_gates.py`](analyze_gates.py)：ECE 是**加權絕對**偏差，有限樣本下恆為正偏；
用 artifact 自帶的逐分箱 game-cluster bootstrap SE（`dev_se`，同一把尺，不引入新變異假設），
在 H0: `dev_b ~ N(0, se_b)` 下算 `E[ECE] = Σ w_b·se_b·√(2/π)`，另以 20,000 次 Monte Carlo
取分位數。近似處（分箱間獨立、常態）已在腳本 docstring 標明方向不定，故只作**量級**判讀，
不當作正式檢定——但量級差距大到判讀不受近似影響。

下列表格全部由 `analyze_gates.py` 產生（[`gate_tables.md`](gate_tables.md)），**未經人工謄寫**。

3. **內部佐證**：`significant_bins = []`——十個十分位沒有任何一個的 99% 叢集 CI 排除 0。
4. **模型其實贏基準**：池化 Brier 0.15009 vs 全押主場 0.25678（表 2）。

> 量的雜訊底線）。處置不變——不得掛警示上線，因為「測不出來」與「測出不好」同樣不足以
> 支撐對外機率數字，但**理由不得寫成模型校準不良**。

- beta 校準後 1-3 帶 dev **−2.58pt**，99% CI **[−5.89, +0.73]pt** → **含 0**。
- base 的「近乎完美」dev **−0.10pt**，99% CI **[−3.41, +3.21]pt** → 同樣含 0。
- 全部 4 帶 × 3 族 **12 格 CI 全數含 0**。

也就是說：「base 近乎完美 → 校準後惡化 2.5pt」是**在同一個 ±3.3pt 雜訊帶內的兩個實現**之間
做比較，而硬性上限（2pt）低於該帶寬。這正是 VAL1 §5 用來廢掉 v1 逐季 ECE 門檻的同一個缺陷，

> **不得讀成「CAL1 可能是 GO」。** §5 的失效機制（校準窗被 2021–22 wf 對主導、
> 學到一個已過時的全域中心下修、受益程度隨與過時窗的距離遞減、isotonic 與 beta 同向）
> 是**結構性論證**，不倚賴上述任何一條閘門，重跑不會推翻它。而池化 Brier 的改善
> （beta 0.15426 vs base 0.15453）本身也在雜訊尺度內。重跑後最可能的誠實結論是
> **「事後校準層的效果與 0 不可區分，無證據支持上線」**——仍是 No-Go，但理由對得上證據。

### 3.6 `ML_FIELD_TZ1_FEASIBILITY.md` → **維持**（正面示範）

NO-GO 的根據是**分類洩漏**：方向桶的歸屬由守備成敗決定（成功記本守位、失敗滾去外野），
實測內野滾地球出局率 89.3% vs 滾出外野 0.2–0.5%、失敗端具名率 ≈0.2%（10/10/17 筆）。
這是**資料生成機制**的性質，對全母體成立，不隨樣本或時間改變。

三準則皆不適用，且該報告示範了正確處理：三輪校準（iteration 1 過度悲觀一律 NO-GO →
iteration 2 過度樂觀條件式 GO → iteration 3 收斂），並明確區分**「數學可識別」與「估得準」**
——後者正是準則 3 要求的詞彙（「網絡連通保證解存在且唯一，但共線性 60–80% + 稀疏橋樑使
信賴區間極寬」）。外野路線的精度也如實給到 ±14 個守備機會／三年。

## §5 自我檢查：有沒有放寬紅線？

卡面明文：「不得以三準則為由把未通過的門檻讀成通過」。逐條自檢：
