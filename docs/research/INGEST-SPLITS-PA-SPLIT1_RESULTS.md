# 結論：**有偏差，已量化**

`splits_calc.py` 確實因與 `GAME-RECAP-PA1-FIX1` **同型**的島切分缺陷而重複計打席。
量化結果（全母體 2018–2026、kind A/C/D/E、4,279 場／1,334,970 事件，
`scripts/verify_splits_pa_split1.py` 產生，逐筆入 `ingest_splits_pa_split1_metrics.json`）：

| 項目 | 數值 |
|---|---:|
| FIX1 認定的誤切在 `splits_calc` 實際**被重複計為 PA** | **61 筆／61 場** |
| 其中被幽靈島規則擋掉 | 0（見下方「與開卡估計的差異」） |
| 因整段無 `batting_action_name` 略過 | 1 |
| **H1 打序位移：受影響的 (場次, 球隊)** | **61** |
| **H1：其後被錯誤歸類打序的 PA** | **1,081 筆** |

重複記的結果詞前幾名：三振 25、四壞 9、一安 4、投滾 3、游滾 3。逐年 2018:2／2019:7／
2020:10／2021:4／2022:10／2023:13／2024:7／2025:6／2026:2。

## H1 成立，且影響遠大於重複計數本身

`flush()` 以 `pa_seq` 累加重建打序（`order = seq % 9 + 1`，因 livelog `batting_order`
是「該半局第幾位打者」而非打序）。**一個多出來的 PA 使該場該隊其後所有 PA 的打序歸屬整體位移 1**
——讀碼推導已由腳本實測證實：61 個 (場次, 球隊) 中，位移之後仍被計入的 PA 共 **1,081 筆**，
全部落入錯誤的家族 10（`ORDER_NAMES`）分箱。

**這是本卡最重要的發現**：重複計數本身只有 61 筆，但污染面是 1,081 筆的打序分項。

## 與開卡估計的差異（61 vs 83）——開卡數字作廢

開卡時的界定腳本用 `pa_build` 的島語意（換人列**不**切界、附掛於前島）重建 legacy 分組，
得 83 對。但 `splits_calc.flush()` 的實際切界是 `(inning, vh, hitter)` 且**只跳過空 hitter 列**
——代打公告列帶著「即將上場打者」的 acnt，**會**切界（這正是該檔「幽靈島」註解描述的現象）。
本次腳本忠實重現 `splits_calc` 的迴圈，故 **61 才是正確曝險，83 作廢**。

> 教訓：「兩處用同一條規則」的判斷必須逐行核對迴圈，不能因規則描述相同就假設行為相同。

## H2：「已與官方對帳過」確實不成立，但另有可用的外部對照

`cpbl-verify-splits` 的 harness 註記明寫「只對『新爬的官方值』有意義（寫回後即自比）」，
而 `cpbl-build-splits` 已寫回官方表且含於每日 refresh——**當前跑 harness 是重算值自比，零資訊**，
卡面紅線 2 的擔憂成立。

**但存在未被污染的外部對照**：`batting_gamelog`（官方逐場 box score）是爬蟲直接寫入、
不經 `splits_calc`。以 2025/A 家族 4（壘包情境，涵蓋全部 PA）對照：

- 174 名選手中 161 名 PA 完全相等
- **splits 高於 box 者恰 3 名**：`0000004633`(+1)、`0000007091`(+1)、`0000001754`(+1)
- 其中 **2 名（4633、7091）正是本缺陷在 2025/A 兩場受影響的當事人**
  （`2025/A/84` 6738→7091 三振；`2025/A/267` 4633→132 四壞）

**尚未解釋的殘留，交查核者**：第 3 名 `0000001754` 的 +1 與本缺陷無對應；另有 10 名選手
splits **低於** box（淨 −12），方向與本缺陷相反、無法由重複計數解釋。故 box 對照
**證實了關聯，但不是零雜訊的證明**——背景差異的成因未查明，可能另有獨立缺陷。

## H3：官方口徑已由 FIX1 釐清，且 box 資料與之吻合

記錄規則 9.15(b)（`docs/reference/棒球規則.txt`，另見 GLOSSARY「打席歸屬」條）：
三振（採 9.15(a) 定義，含 (a)(3) 不死三振）由代打者完成 → 記「被判第 2 好球者」；
其他結果（含四壞）→ 記代打者。

`2025/A/84` 的官方 box 與此吻合且更精細：`7091`（完成者）`PA=1, AB=0, SO=0`、
`6738` 該場 `PA=3, AB=3, SO=2`——**官方把「打席數」記給完成者、「打數與三振」記給
被判第 2 好球者**。無論如何，官方**只計一個打席**，`splits_calc` 計兩個即為偏差。

## 邊界與未做

- **本卡未修**（卡面紅線 5）：`splits_calc.py` 零改動，未跑 `cpbl-build-splits`，未寫任何分項表。
- **未量化到「哪些選手的哪些分項欄位差多少」的完整清單**：61 筆重複與 1,081 筆打序位移的
  逐筆明細已在 artifact，但轉換成「每位選手每個 item_name 的欄位差」需要重跑 `splits_calc`
  的兩個版本對照——那會觸及寫入路徑，屬修正卡的範圍。
- H2 的背景雜訊（+1 未解釋 1 名、−1 方向 10 名）未查明成因。

## 建議

開修正卡（`db_scope: data-migration`）：`splits_calc.flush()` 的切界改引用
`continues_same_plate_appearance`，重算四張分項表與生涯分項。**修正前必須先解決 H2 的
對照問題**——重算後 harness 仍是自比，需以 `batting_gamelog` 或重新爬取的官方值作為驗收對照。
