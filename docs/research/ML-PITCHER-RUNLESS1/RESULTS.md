不含執行時間）。**刻意排除保留賽**：保留賽的 `game_date` 是改期後的未來日期而比分已
記上（實例 `2026/D/165`：`orig_date` 07-17、`game_date` 09-15、比分 1:3），直接取
`max(game_date)` 會把 as-of 標成 2026-09-15——那是把**排程日期**誤讀成**資料新鮮度**。
原始最大值仍以 `latest_game_date_any` 揭露（D 層為 2026-09-15），不做沉默捨棄。

重跑後想知道「數字為什麼不一樣」，用 `--compare-to`（§2.2），它會把差異歸因到
**輸入變動**或**同一份輸入卻算出不同結果**——後者才是缺陷。

### 1.1 9.16 的措辭（**卡面 2026-08-07 修訂版，請勿退回舊版**）

舊版寫「改做連續無失分可**完全繞開 9.16**」——**不成立**。9.16(g) 本文即為失分歸屬的
規範性條款，原文（`docs/reference/棒球規則.txt` **L6208-6211**，本次重新查證；卡面記
L6208-6210，句尾「援投手之責任」實際落在 L6211，以本次查證為準）：

> （g）在同一局中更換投手，在後援投手上場後壘上原有之跑壘員得分，或利用野手選擇使前任
> 投手遺留的跑壘員出局，因此進壘而得分者，該失分（**無論自責分或非自責分**）皆不為
> 後援投手之責任。

正確的措辭是：**該歸屬已由聯盟記錄員套用於官方逐場 `runs` 欄，我方直接讀取、不重算。**
真正繞開的是 9.16 的**主觀條款**——(c)(d) 的反事實重播（「若無失誤是否仍能得分」）與
(f)「在判斷跑壘員是否因失誤而進壘有疑慮時，應對投手有利為宜」（L6206-6207，同次查證）。
失分口徑完全不碰這三條。

### 1.2 為什麼「兩段口徑一致」是真的（而現行實作不是）

現行自責分口徑的兩段各自證明不同的命題：

| 段 | 現行（自責分） | 本卡（失分） |
|---|---|---|
| 中段 | 該出賽官方 `earned_runs = 0` | 該出賽官方 `runs = 0` |
| 尾段 | 該局官方逐局**得分**為 0 | 該局官方逐局**得分**為 0 |

尾段判準本來就是**失分**口徑的證據。接在自責分中段上時，它證的是「零得分 ⇒ 零自責分」
這個**跨口徑蘊含**；接在失分中段上時，它與中段是**同一個量的兩個粒度**（出賽 vs 局）。

**必須說清楚的界線**：這不代表現行實作會高估。尾段的證明較強（連非自責分都沒有），
混用的結果仍是自責分口徑的合法下界——`ML-PITCHER-SCORELESS1` §1.5 需求方裁定即為此。
本卡改善的是**證據標準的齊一性**與**名詞與媒體用語的對應**，不是正確性。

**也不代表採計率會變好。** 見 §4。

### 2.2 輸入漂移偵測：分辨「輸入變了」與「算錯了」

**問題**：母體每天長大，所以「重跑數字不一樣」永遠會發生。若把它一律當成 artifact 過期
去追著更新，那是跑步機；若一律當成通過，守衛就等於沒有。

**做法**：每次執行輸出 `fingerprint` —— as-of ＋ 母體規模 ＋ **每一條輸入通道各自的
內容指紋**。本模組讀的輸入只有三條，各有一個 `*_digest`：

| 通道 | digest | 來源 |
|---|---|---|
| 出賽 | `appearance_digest` | `pitching_gamelog` ＋ join 進來的 `games` 欄位（即 `Appearance`） |
| 球員姓名 | `name_digest` | `pitching_gamelog.pitcher_name`；不參與演算法，但**會寫進 artifact** |
| 逐局比分 | `scoreboard_digest` | `game_scoreboard` 原始列（不做 `max()` 聚合，比載入層更嚴格） |

出賽側的指紋**直接由已載入的 `Appearance` 物件算出**，不另寫平行 SQL——平行 SQL 會和
載入層各自演化，指紋就會慢慢不再代表輸入。逐列以 JSON 序列化再雜湊，`null`／`0`／
字串 `"0"` 各有不同表示（測試 `test_digest_does_not_fold_unknown_into_zero`）。

### 涵蓋範圍為什麼不會再過期（iteration 4 的核心修正）

iteration 3 的指紋是**手寫的 12 個欄位、漏了 `opponent`**。查核者只把對手由甲隊改成
乙隊，指紋不動 → 不同的輸入、不同的 artifact 被判成 `identical`。**補上 `opponent`
不算修好**：下一個人往 `Appearance` 加欄位，同一個洞會再開一次。

三處原本各自維護一份手工清單，本輪全部改成由來源導出：

| 位置 | iteration 3（手寫） | iteration 4（導出） | 新增東西時 |
|---|---|---|---|
| 指紋涵蓋的出賽欄位 | 12 個欄位的 tuple | `dataclasses.fields(Appearance)` | **自動納入** |
| 分類器比對哪些指紋 | 寫死 `appearance`／`scoreboard` 兩個名字 | 兩邊 fingerprint 中**所有 `_digest` 結尾的鍵**取聯集 | **自動納入** |
| 漂移報表顯示哪些指紋 | 寫死同樣兩個名字 | 逐一列出判定為變動的 digest，**查不到人類標籤就印鍵名** | **自動顯示** |

第三列是本輪自己踩到的：修完前兩處後 `name_digest` 確實變動了，報表卻不顯示——**輸出層
漏顯示與指紋漏欄位是同一種病**。預設行為因此改成偏向「顯示」而非「靜默」。

**守衛與被守衛的東西共用同一個來源**：回歸測試
`test_every_appearance_field_moves_the_digest` 以
`@pytest.mark.parametrize` 走同一個 `dataclasses.fields(Appearance)` 迴圈，逐欄位變異
並要求指紋跟著變。新增欄位時它會自動多出一個參數化案例；欄位若沒進指紋，該案例就以
欄位名失敗。**這不是「我記得更新清單」，是型別變了測試自己就變。**

另有 `test_every_artifact_item_key_is_traceable_to_a_digested_input`：artifact 的每個
item 欄位都必須能歸到「`Appearance` 欄位／`player_name`／演算法衍生值」三類之一，
未分類的新欄位會失敗。**這條不宣稱涵蓋完整，它宣稱的是「未分類的欄位不會靜默通過」。**

### 殘留風險（照實列）

- **指紋不涵蓋程式碼版本**：`mismatch_same_input` 只證「不是資料造成的」，不指出是什麼
  造成的（程式碼變更與執行環境都是候選）。刻意的範圍限制，不要讀成根因判定。
- **新增的輸入通道若不叫 `*_digest`**，分類器不會納入。命名約定寫在
  `population_fingerprint` 的 docstring，並由
  `test_classifier_compares_every_digest_key_not_a_hardcoded_pair` 釘住行為，
  但**這一條靠約定，不是靠型別**——這是本輪剩下的最弱環節。
- `_DERIVED_ITEM_KEYS` 仍是人工分類清單。它的失效方向是**fail-closed**（未分類即失敗），
  但分類本身若被錯填（把真正來自新資料源的欄位塞進衍生值），測試不會發現。

```bash
uv run python scripts/reconcile_scoreless_streak.py \
  --compare-to docs/research/ML-PITCHER-RUNLESS1/RECONCILE.json
```

| 判定 | 條件 | 意義 | exit |
|---|---|---|---|
| `identical` | **所有** digest 相同、追蹤欄位相同 | 同一份輸入、同一份輸出 | 0 |
| `input_drift` | **任一** digest 不同 | 母體長大、既有場次被修訂、或指紋定義本身改了——只報漂移量 | 0 |
| `mismatch_same_input` | 所有 digest 相同、追蹤欄位**不同** | 同一份輸入卻給出不同輸出 | **1** |

舊 artifact 少了某個 digest 鍵時**偏 `input_drift` 而非 `identical`**：無法證明輸入相同
就不要說相同，`identical` 是會讓缺陷靜默通過的那一邊。

#### 示範輸出（四種情境都實跑，不是設計說明）

`--data-asof-cutoff` 可重建較舊的資料截點（**稽核用；正式 artifact 一律不帶 cutoff**）。
以 2026-07-31 為截點重建再與現況比：

## 5. 並列 vs 取代：建議 → **需求方裁決：並列**（2026-08-08）

**裁決（Issue #106，需求方原文「123 按你建議」）：並列。**
`GET /api/v1/records/run-free-streak`（失分口徑）為**預設呈現面**，自責分口徑保留為
並行紀錄與零推論稽核基準。§5.1／§5.2 是 iteration 1 提出的建議與證據（原樣保留）；
§5.3 的反面意見**被列管、不視為已解決**；§5.4 是裁決同時定案的欄位回填，
§5.5 記錄它造成的相容性破壞。

### 5.1 支持並列的證據

1. **兩者確為不同紀錄**（X1：一軍 2,163 筆出賽 `runs ≠ earned_runs`），不是同一個數字的
   兩種說法；刪掉一個就是刪掉一個真的指標。
2. **自責分口徑有它自己的用途**：它與 ERA 語意一致，且**不受記錄員失誤判定影響**——
   一個守備失誤的判定不會改變它。失分口徑則會。兩個問題不同：「這位投手表現得多乾淨」
   vs 「這支球隊多久沒讓對手踏過本壘」。
3. **並列的邊際成本接近零**：同一套演算法、同一支對帳腳本、同一組 R1–R10。新增的只有
   一個 `Basis` 設定與一個端點函式；`compute_streak` 的可執行邏輯沒有分岔（判準值一律
   走 `Basis.charged()`）。
4. **失分口徑的值恆 ≤ 自責分口徑**（X3 逐人驗證），所以並列不會出現「兩個數字互相打臉」
   的情形，只會是「較嚴格的那個 ≤ 較寬鬆的那個」，可直接用一句話解釋給讀者。

### 5.2 支持失分作為**預設呈現面**的證據

1. **名詞對得上讀者手上的數字**：兩筆 media 的用詞都是「無失分」。現行端點必須永遠帶著
   紅線 5 的警語說明「這不是無失分」——那個警語存在本身，就是名詞與讀者預期不一致的證據。
2. **口徑一致**：§1.2 的兩段同量論證。
3. **較保守**：X3 保證失分口徑恆 ≤，headline 數字不會比另一個口徑大。

### 5.3 反面意見（照實列，不藏）——**需求方已列管，未解決**

裁決留痕明文把以下兩項收為列管事項、**不視為本卡已處理**：

- **並列會在站上出現兩個長得很像的數字**，讀者會問「到底哪個是紀錄」。這是真實的產品
  成本，需要文案紀律（兩支端點的 `metric_label`／`note` 已強制帶「自責」或「失分」二字，
  但前端仍需刻意設計主從呈現，不是並排兩個數字讓讀者自己猜）。**這在前端消費時才會
  真正發生，本卡沒有解決它。**
- **兩支端點目前都沒有前端消費者。** 自責分那支上線至今 `web/` 零消費者；本卡再加一支，
  等於未被消費的介面翻倍。**裁決不改變這一點**；需求方裁示若一季後仍無消費者，應回頭
  檢討是否保留兩支。

第三點（若裁為取代該取代什麼）已因裁決為並列而不適用，保留備查：`EARNED_RUN_BASIS`
不該被拆掉，因為 `strict_outs` ＋ R1 是零推論的稽核基準——這一點在並列裁決下自動成立。

### 5.4 iteration 2：揭露欄位回填自責分端點（需求方定案）

裁決同時定案：`basis_field`／`lower_bound_note` **回填至自責分端點**。理由是並列的前提
就是兩支對外語意對稱——只有一支帶揭露欄位，讀者無從判斷另一支的判準欄位與下界性質，

**不是「向後相容的新增欄位」。** 對做嚴格 key 比對的消費者而言，多一個 key 就是破壞——
iteration 1 正是以這個標準拒絕回填的（當時卡面寫「既有端點行為不得改變」），本輪維持

## 6. 誠實揭露：下界限制**不因改用失分口徑而消失**

**中途登板／中途退場、且該場後段仍有得分時，該場仍只能給鴿籠下界（多半為 0）。**
成因是官方逐場只記整場的量、不記事件時點，**與判準用 ER 還是 R 無關**。

實測（`RECONCILE.txt`，**as-of 2026-08-07**；尾段查詢＝分母）：

| 層級 | 口徑 | 尾段查詢 | 尾段採計 | 採計率 | 尾段出局數 |
|---|---|---|---|---|---|
| 一軍 A | 自責分 | 345 | 25 | 7.2% | 162 |
| 一軍 A | **失分** | 346 | **24** | **6.9%** | **156** |
| 二軍 D | 自責分 | 492 | 19 | 3.9% | 160 |
| 二軍 D | **失分** | 502 | **22** | **4.4%** | **180** |

一軍側**略降**、二軍側略升——差異來自中斷場落在不同場次，**不是方法改善**。
換句話說：**口徑一致化沒有買到任何採計率**，也不宣稱買到。

（這幾個數字同樣繫在 as-of 上：iteration 2 的 08-06 版是一軍 25→24 場、132／126 outs，
二軍 20→23 場、161／181 outs。方向結論——一軍略降、二軍略升、量級同一檔——兩個 as-of
都成立，但**請勿把任一組數字當成固定值引用**。）

保留的具體反例（`SCORELESS1_RESULTS.md` §3.2）：黃子鵬 2026-07-26 第 1 局失分、投完第 6 局，
